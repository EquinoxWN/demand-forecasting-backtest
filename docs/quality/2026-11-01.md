# Quality check 2026-11-01

The ten quality rules checked against the M1 code (file name kept the same as in the other repos;
the check was done on 2026-11-12 while M1 was built). Python 3.14.5 venv, Windows 11, CPU only.
The only external call is the M5 download; everything else is local file reading and NumPy work.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | `download` (`data.py`) uses `urlopen(..., timeout=60)`, HTTPS only, a 60 MB cap and a SHA-256 check; network errors (`URLError`, `TimeoutError`, `ConnectionError`) are retried at most 3 times with 1 s and 2 s backoff, then raise `DataError` (`test_transient_failures_are_retried_with_backoff`, `test_retries_are_bounded_and_leave_no_partial_file`). A checksum mismatch is not retried. Every `except` re-raises as `DataError` with the cause or exits 2 with the message (`cli.py`); ruff `BLE`, `S110`, `E722` clean; no `except: pass`. |
| 2 | Writes safe to retry | pass | The download writes a per-process `.part` file and renames it after the checksum matches; a verified file is not fetched again (`test_a_verified_file_is_not_downloaded_again`). Feature tables and JSON go through `files.atomic_text` (temp file + `os.replace`); gzip with `mtime=0`, so a re-run gives identical bytes (`test_feature_export_is_complete_and_repeatable`); a failed write keeps the old file (`test_a_failed_write_keeps_the_old_file`). |
| 3 | No race conditions | pass | Single-threaded; no shared mutable state. Found while checking: the partial download file had a fixed name, so two processes downloading to one path would write into the same file; it is now named per process (`data.py`, `download`). |
| 4 | Don't trust the clock | pass | Durations use `time.perf_counter` (`cli.py`, `_backtest`). The only stored time, `created_utc` in the JSON output, is `datetime.now(UTC)` (`test_backtest_prints_the_table_and_writes_json` checks `+00:00`). Dates in the data are calendar days from `calendar.csv`, not clock readings. |
| 5 | Read before changing | pass | APIs checked by `mypy --strict` against pandas-stubs and NumPy. No environment variables are read (README says so); temporary files for `--synthetic` use the standard `tempfile` location. Paths in docs exist (`audit_repo.py` checks README links). |
| 6 | Never break compatibility | pass | First release. The loader accepts both the Kaggle calendar (with `d`) and the mirror's (without), tested. Output formats are new; the CSV header order is fixed by the code and tested. |
| 7 | One source of truth | pass | The archive is checked against one pinned SHA-256 (`M5_SHA256`, with its date and origin in a comment) and re-downloaded if it does not match. Store and total levels are always recomputed from item sales, never stored separately (`test_levels_add_up`). Python version: `requires-python >=3.11`, README 3.11+, CI 3.12. |
| 8 | Small changes, no secrets, validate input | pass | No secrets or tokens (the mirror needs no sign-in). Inputs validated: store list format and horizon range (CLI), output suffix, every CSV's columns, day order, value ranges and duplicates (16 malformed-file cases), unknown stores, missing files, bad archives. Dependencies: NumPy and pandas only. |
| 9 | Tests that can fail | fixed | No skips, xfails or assertion-free tests. Mutation table below: 9 of 12 killed by the first suite; three tests added; 12 of 12 killed. Empty, invalid and failure paths are covered for each public entry point (`load_m5`, `download`, forecasters, metrics, `evaluate`, CLI). |
| 10 | Re-verify | pass | `ruff check`, `ruff format --check`, `mypy --strict`: clean; `pytest`: 69 passed; `pip-audit`: no known vulnerabilities; `.tmp/check.sh` printed `CHECK PASS` twice; `audit_repo.py`: OK. CI has not run yet (not pushed). |

## Known limitations

- The pinned SHA-256 is the hash of the mirror's archive on 2026-11-11; no checksum is published
  upstream, so the first download was trusted.
- All ten stores at once need several gigabytes as float64 matrices; M1 runs one store at a time.
